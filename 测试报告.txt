一、此次故障根因与修复
----------------------
用户实际 Windows 报错：
  syscall: string with NUL passed to StringToUTF16

根因：
“导出完整 TXT”在调用 Win32 GetSaveFileNameW 前，文件过滤字符串需要使用 NUL 作为显示名/通配符分隔符；旧代码把包含 NUL 的字符串直接传入 syscall.StringToUTF16，Go 会主动 panic。

修复：
1. 新增 buildWin32FilterUTF16，允许 OPENFILENAME 过滤器包含内部 NUL，并保证末尾双 NUL。
2. chooseSave 不再对 filter 调用 syscall.StringToUTF16。
3. 新增 safeWindowsFileName，清理 Windows 文件名非法字符。
4. 新增 ExportFullNovel，并对实际写文件错误进行检查与提示。
5. Win32 普通文本入口增加 NUL 清理保护，避免损坏/异常历史数据触发同类 panic。
